# AskBack AI 老師：流程說明

skill 本體在 repo 根目錄（`SKILL.md`、`scripts/`）。

> 2026-10-14 版：已在 RTX 3090 上實跑（clone 配音＋Remotion），結果見根目錄 README〈實測〉。

## 原理：agent 負責想，程式負責做

工作切成兩半：

- **要判斷的事交給 agent**（Claude Code 或 Codex 本身）：學生卡在哪、怎麼解釋、用哪種形式、畫面放什麼。agent 本來就看得懂截圖、讀得懂字幕，所以不另外呼叫 VLM 或 LLM。
- **每次都一樣的事交給程式**：截圖、語音辨識、分析老師的聲音、驗算、配音（clone 老師聲線）、排時間軸、畫畫面、合成影片。寫成固定腳本，每題用同一套流程，比較不容易出錯。
- **預設環境有一張 RTX 3090**：語音辨識（Whisper large-v3）、聲音分析、voice-clone TTS、合成品管都跑本機模型，不用金鑰。每一步都有無 GPU 的備援。

兩邊的唯一介面是 agent 寫的一份 `work/lesson.json`，也就是這支影片的分鏡腳本。

```
input/ ──look.py──▶ work/look/ + work/voice/ ──agent 看、想、寫──▶ work/lesson.json ──render.py（speak.py 配音 → Remotion／Pillow 畫面）──▶ output/askback.mp4
```

核心規則：

1. 一支影片只解一個困惑。
2. 一句話只做一件事（一句旁白＝一個畫面動作）。
3. 一個畫面只放一個重點。
4. 能沿用原片的，就不要自己做。
5. 能算的，就不要用想的。

## 輸入

作業規定的 `input/` 資料夾：

| 檔案 | 內容 |
|---|---|
| `case_input.json` | 學生問題、提問秒數、年段科目、已知概念、可能的迷思、影片講到哪裡、來源標示 |
| `prefix.mp4` | 原片從頭到提問時間的片段 |
| `prefix.vtt` | 到提問時間為止的字幕（20 題中只有 9 題有） |

## 輸出

放在 `input/` 同一層的 `output/`：

| 檔案 | 內容 |
|---|---|
| `askback.mp4` | 交付的影片：1280×720、30–90 秒、有旁白、燒進去的字幕、「AI 生成教學示範，非原講者本人」角標、均一來源標示 |
| `preview.jpg` | 每一句講完時的畫面拼成一張圖，給 agent 回頭檢查排版 |
| `lesson.json` | 這支影片用的腳本副本 |

## 過程：四步

### 1. 看：`scripts/look.py`

把影片轉成 agent 讀得懂的材料，放在 `work/look/`：

- **`case.txt`**：從 `case_input.json` 整理出的題目重點。
- **`overview.jpg`**：用 ffmpeg 從整段 prefix 平均截 12 格拼成一張，讓 agent 判斷原片形式和節奏。
- **`end_1.jpg`–`end_4.jpg`**：提問前 20、10、4、0.5 秒的原尺寸截圖，也就是學生卡住時看到的畫面。
- **`palette.txt`**：從最後一格算出背景色和強調色（依色相分群）。
- **`transcript.txt`**：逐字稿，依序嘗試三種來源：
  1. 有 `prefix.vtt` 就直接用。
  2. 有 `OPENAI_API_KEY` 就用 OpenAI whisper-1 辨識。
  3. 否則用本機的 faster-whisper（有 GPU 用 large-v3，沒有用 small）。
- **`work/voice/`**（`scripts/voice.py`，look.py 自動呼叫）：silero VAD 找講話段落 → librosa pyin 量音高 → 兩個說話者（角色劇）時依音高分群取講最久的那位 → 算語速（字/秒）、停頓 → `profile.json`（含建議語速 `rate`、聲音庫配對 `match`）。再從主要說話者挑 4–12 秒最乾淨的段落（連續講話、訊噪比高、不在片頭）存成 `teacher.wav`，用 Whisper 聽寫成 `teacher.txt`，另存 `ref_1..3.wav` 候選。這就是 clone 用的 one-shot 參考音檔。

  三種都沒有就跳過，靠截圖和 `context_summary` 也能做。
- 另外可用 `look.py --at 02:38` 截指定時間的畫面，當作影片裡的圖。

### 2. 想：agent 自己做，沒有程式

`SKILL.md` 要求 agent 先回答四個問題：

1. 學生哪裡想對了？
2. 卡在哪一步？
3. 一句話的答案是什麼？
4. 原片會怎麼教？

答案寫成 `answer_in_one_sentence`，寫不成一句就表示還沒想清楚。有數字的地方要寫成可驗算的算式；不確定的概念可以查一般教科書層級的資料，但不准查這部影片本身或它的後續內容。

### 3. 寫：agent 產出 `work/lesson.json`

這份腳本描述整支影片：

- **`style.form`**：四種形式擇一，依原片選。
  - `board`：黑底、芫荽手寫字，算式逐字寫出來。
  - `slides`：淺底、Noto Sans 字，淡入。
  - `story`：角色對話泡泡，不同角色用不同聲音。
  - `lab`：以原片截圖為主，在上面圈、指、標。
- **`checks`**：算式清單，例如 `"1598 - 260 == 1338"`。
- **`scenes` → `beats`**：每個 scene 是一個畫面，每個 beat 是一句旁白。每句有：
  - `say`：要唸的文字（數字寫成唸法）。
  - `sub`：字幕（數字寫成符號，可省略）。
  - `show`：這句話出現的畫面元素，只有三種：一行字（`line`）、一個標記（`shape`：圈、框、箭頭、多邊形、標籤等）、擦掉（`clear`）。

句數與字數有建議值：6–10 句、180–280 字，約 45–70 秒。結構固定五段：

| 段 | 做什麼 | 句數 |
|---|---|---|
| 接住 | 肯定學生想對的部分，複述問題 | 1 |
| 點破 | 指出卡住的那一點 | 1–2 |
| 示範 | 用原片的例子一步一步做 | 3–5 |
| 收束 | 一句話結論 | 1 |
| 銜接 | 回到原片，只說 `context_summary` 提到的下一步 | 1 |

### 4. 做：`scripts/render.py`

依序執行：

1. **驗算**：用 Python 的 `ast` 安全地計算每條 `checks`（只允許數字運算、分數、根號、三角函數等），任何一條不成立就停下來，不出影片。
2. **配音**（`scripts/speak.py`）：每句 `say` 各自合成語音。
   - 有 GPU 而且 `tts_local/` 裝好：**clone 後端**。所有要合成的句子一次交給 `tts_local/engine.py`（模型只載入一次），以 `work/voice/teacher.wav` 為參考 zero-shot 合成；每句合成 3 次（換 seed），用 Whisper large-v3 聽回來算 CER，留最準的一次；殘留的阿拉伯數字由 `zhnum.py` 轉成中文讀法；多音字可在 `say` 裡標注音 `字[:ㄔㄤ2]`。引擎預設 BreezyVoice（臺灣國語），備援 CosyVoice3（`adapters/`）。選型理由見 `2026-10-14_技術決策備忘錄.md`。
   - 否則依序嘗試 edge-tts（免費、不用金鑰，臺灣華語聲音 HsiaoChen、HsiaoYu、YunJhe；某個聲音壞掉會自動換）→ OpenAI TTS → gTTS → 系統語音。
   - 用 ffmpeg 轉成 wav、響度正規化、裁掉頭尾靜音。
   - 依「後端＋聲音＋語速＋句子」做快取，改 lesson 重跑時沒動到的句子不會重新合成。
   - 語速：edge-tts 跟原片（`profile.json` 的 `rate`），lesson 的 `style.rate` 可覆寫。clone 時不再套這個 rate（模型已經從參考音檔學到老師的語速），要調整用 `style.clone_rate`。
   - 沒有 GPU 又沒有 clone 快取時，不在 CPU 上跑 clone 模型（太慢、太吃記憶體），直接改用 edge-tts；clone 失敗（例如找不到聲音）也會退回 edge-tts。
3. **排時間軸**：每句的起點由前面各句的實際語音長度累加，句間預設停 0.35 秒，可用 `pause` 加長。改一句只影響後面的起點，不會錯位。預計總長超過 90 秒時，整條旁白等比例加速（ffmpeg atempo，不變音高），最多 1.15 倍；還是太長就要 agent 刪句子。
4. **畫畫面**：預設 **Remotion 引擎**（`remotion/`，React；每秒 30 格）：render.py 先用 Pillow 的字型度量算好字級、欄寬、圖區，把解析好的文字標記與時間軸寫成 `work/remotion_props.json`，Remotion 只負責「怎麼動」：板書逐字從左寫到右（筆尖有光）、投影片重點淡入上浮、角色泡泡 spring 彈出、圈與箭頭沿路徑畫出來、同一句的多個元素依序出現；全部用 spring／bezier easing、兩端 clamp。沒有 node 或 Chrome 開不起來（例如計算節點缺 `libnss3`）就自動退回 **Pillow 引擎**（每秒 20 格，逐格畫）。兩個引擎吃同一份 lesson.json，排版一致。
   參考了 haidrrrry/claude-remotion-skill 的動態規則，但故意不用它的背景漸層、顆粒、暗角、Ken Burns、呼吸動態——那些會讓畫面不像原片的板書或投影片。
   - 每句開始後，新元素在一小段時間內出現：板書逐字寫出、投影片淡入、圈從 0 畫到 360 度、箭頭慢慢延伸。
   - 字的上色、圈起、劃掉、底線、上下標、分數都由程式排版；字型隨 repo 附上，缺字會自動換另一個字型。
   - 放不下時整個畫面的字一起縮小，縮到下限還放不下就報錯，要 agent 刪內容。
   - 每格都加上角標、字幕、來源標示。
5. **合成**：畫好的畫面直接以原始像素送進 ffmpeg，配上拼好的整條旁白 wav，編成 H.264 加 AAC 的 mp4。
6. **檢查**：確認長度在 30–90 秒內，不符合時告訴 agent 大約要刪或補幾個字，並輸出 `preview.jpg`。

agent 最後要打開 `preview.jpg`，照 `SKILL.md` 的清單自我檢查（年段用詞、正確性、排版、是否用到提問後的內容），有問題就改 `lesson.json` 重跑。

## 用到的東西

| 類別 | 項目 | 是否必要 |
|---|---|---|
| 判斷與撰寫 | 執行 skill 的 agent 本身 | 必要 |
| 影音處理 | ffmpeg（系統的跑不起來就用 `imageio-ffmpeg` 附的） | 必要 |
| 畫面 | Remotion（React，需要 node 18+，`setup.sh` 會裝到 `~/.local`）；備援 Pillow、fontTools（找缺字） | Pillow 必要，Remotion 預設 |
| 字型 | 芫荽 Iansui、Noto Sans TC，SIL OFL 授權，放在 `fonts/` | 隨 repo 附 |
| 語音 | **BreezyVoice-300M**（MediaTek Research，本機 GPU，clone 原片老師）；備援 CosyVoice3、edge-tts（微軟線上服務，免費免金鑰）、OpenAI TTS、gTTS、系統語音 | 有 GPU 用 clone，否則 edge-tts |
| 聲音分析 | silero VAD、librosa（音高、語速、挑參考音檔） | 必要（look.py） |
| 逐字稿與配音品管 | faster-whisper large-v3（GPU；沒有 GPU 用 small）或 OpenAI whisper-1 | 選用 |
| 插圖 | `paint.py` 呼叫 OpenAI 生圖（gpt-image-2，失敗改 gpt-image-1），只畫沒有字的圖 | 選用，沒測過 |

不用任何金鑰就能跑完整條流程。

## 三支測試影片的畫面來源

| 影片 | 形式 | 圖從哪裡來 |
|---|---|---|
| `V03.mp4` 加減併式 | `board` | 沒有圖，全部是程式排版的算式 |
| `V13.mp4` 豬心動脈 | `lab` | 第一段用原片 01:28 的截圖，加上程式畫的圈和標籤；第二段的心臟、肺、箭頭是用 shape 畫的簡圖 |
| `V01.mp4` 認識昆蟲 | `story` | 原片 02:38（螞蟻）和 02:05（蜘蛛）的截圖，加上程式畫的標籤和圈 |

三支都沒有用到生圖模型。

## 沒驗證過的部分

- 範例的三份 `lesson.json` 是開發時手動寫的，還沒讓一個全新的 agent 只讀 `SKILL.md` 就寫出來。
- OpenAI 的語音、辨識、生圖備援，因為沒有金鑰都沒實際跑過。
- CosyVoice3 adapter 只寫好，沒有實跑。
- 真的有兩個人講話的角色劇、背景音樂很大的影片，抽參考音檔的效果還沒驗證。

已驗證（2026-10-14）：Mac 與 Linux 都能跑；RTX 3090 上 `setup.sh --tts`、Whisper large-v3、BreezyVoice clone、Remotion 三題都出片。
